## Priority summary

- **GAP-001** (P1): The look-alike domain was not blocked on the first visit, so the credential harvest happened with no proxy or DNS barrier.
- **GAP-002** (P1): The lure reached dmarsh with no evidence of mail-gateway scanning, so the first attacker action was never tested.
- **GAP-003** (P1): A conditional access exception suppressed the risk signals on the foreign-IP session, so the one control that flagged the intrusion was switched off.
- **GAP-004** (P1): No geo/IP block stopped sign-in from RU, so a single named-location rule would have stopped the session outright.
- **GAP-005** (P1): Risk signals never reached an analyst, so the session from 45.63.9.88 has gone untraced for the whole investigation.
- **GAP-006** (P1): Encoded hidden PowerShell and an unsigned binary from %TEMP% ran unblocked, so the ASR rules are the earliest point to stop the chain.
- **GAP-007** (P1): The Run-key persistence write was logged but not alerted, so the machines stayed persistent until the isolation.
- **GAP-008** (P1): MSBuild loaded an inline task from a user Temp path on two hosts, so a path-scoped MSBuild rule with a C:\src exemption closes the LOLBin step without breaking builds.
- **GAP-011** (P1): LSASS access left no telemetry or block while reusable NTLM material for dmarsh sat in memory, so the credential theft was invisible.
- **GAP-012** (P1): RunAsPPL and Credential Guard were not enforced, so any process running as admin could read lsass on WST-WS-031.
- **GAP-013** (P1): The Kerberos type 3 logon to WST-WS-017 was not flagged, so the lateral hop had no detection point.
- **GAP-014** (P1): Workstation admin shares allowed a PHI copy between peers, so disabling AutoShareWks and blocking TCP 445 removes the path.
- **GAP-015** (P1): Fourteen PHI reads in one burst generated no alert, so the bulk-access signal was lost.
- **GAP-016** (P1): LIS-WSIDE-01 handled the PHI reads and copy but was never isolated, so an active source of PHI access may still be online.
- **GAP-017** (P1): No DLP stopped the bulk copy and exfiltration has not been ruled out, so the PHI breach scope is still open.
